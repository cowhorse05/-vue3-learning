# 02｜响应式与组件：为什么数据变了，界面会变

## 1. 核心模型

Vue 会在渲染时读取响应式数据并追踪依赖。数据变化后，对应的界面更新。你写的是“界面应当是什么样”，不用在每次请求成功后手写 DOM 查找和替换。

```ts
const status = ref('Pending')
status.value = 'Approved' // 使用 status 的模板会更新
```

把它类比为“带订阅关系的状态”即可；不要把它误当作跨机器同步、数据库监听或可靠事件总线。组件销毁、页面刷新、浏览器关闭时，普通内存状态不会自动持久化。

## 2. `ref` 与 `reactive`

```ts
const keyword = ref('')                 // JS 中 keyword.value
const list = ref<Sandbox[]>([])         // 对象和数组也能用 ref
const filters = reactive({ status: '', page: 1 }) // 字段 filters.status
```

| 用法 | 特点 | 常见场景 |
| --- | --- | --- |
| `ref(value)` | 访问 `.value`；换掉整个值自然 | 搜索词、loading、列表、当前详情 |
| `reactive(object)` | 属性访问直观；代理对象 | 多个相关筛选字段、表单 |

模板里普通 `ref` 可直接写 `{{ keyword }}`；脚本里通常写 `keyword.value`。`reactive` 对象里的字段要谨慎解构：`const { status } = filters` 若得到的是普通字符串，之后它不会自动跟随对象变化。用 `toRefs(filters)` 或 getter 传给 `watch`。

```ts
const { status } = toRefs(filters)
watch(() => filters.status, value => console.log(value))
```

**读源码关心什么**：状态在哪里声明、哪些函数写入、哪个模板或计算依赖读取。不要只背“基本类型用 ref、对象用 reactive”；`ref` 完全可以包对象。

## 3. `computed` 与 `watch`

`computed` 是由已有状态计算出的值：

```ts
const canRetry = computed(() =>
  ticket.value.status === 'ApplyFailed' && user.value.role === 'Admin'
)
```

`watch` 是当数据变化时做动作：

```ts
watch(
  () => [filters.status, filters.page],
  () => { void loadList() },
  { immediate: true },
)
```

`immediate` 使侦听器建立时先执行一次；之后依赖变化再执行。`watchEffect` 自动收集执行时读取的响应式值：

```ts
watchEffect(() => console.log('当前筛选:', filters.status))
```

复杂的 HTTP 请求通常更容易用显式 `watch` 说明“为什么发起”。如果旧请求比新请求晚返回，旧数据可能覆盖新条件的结果；可以使用取消请求、请求序号或验证返回结果对应当前参数。

```ts
let requestVersion = 0
async function reload() {
  const version = ++requestVersion
  const result = await listSandboxes(filters.status)
  if (version === requestVersion) items.value = result
}
```

课程里多种 `watch` 情况的本质是：监听源可以是 ref、对象、getter、数组；对象内部变化与整体替换是否触发需要看源和配置。审查时明确监听目标与副作用，不要无意中在 `watch` 内修改自己监听的值，造成循环。

## 4. `ref` 属性与 DOM

```vue
<script setup lang="ts">
import { onMounted, ref } from 'vue'
const searchInput = ref<HTMLInputElement | null>(null)
onMounted(() => searchInput.value?.focus())
</script>
<template><input ref="searchInput" /></template>
```

模板的 `ref` 指向 DOM 元素或组件实例。元素没挂载前值通常是 `null`。用它做聚焦、测量尺寸等；不要把访问子组件内部实例当成默认通信方式。

## 5. 组件边界与事件

父组件负责持有列表及发请求，表格负责展示：

```vue
<!-- 父组件 -->
<SandboxTable :items="items" @stop="handleStop" />
```

```vue
<!-- 子组件 SandboxTable.vue -->
<script setup lang="ts">
defineProps<{ items: Sandbox[] }>()
const emit = defineEmits<{ stop: [id: string] }>()
</script>
<template>
  <button v-for="item in items" :key="item.id" @click="emit('stop', item.id)">
    停止 {{ item.id }}
  </button>
</template>
```

`props` 是父到子输入；`emit` 是子向父报告事件。这样同一表格可复用，父组件能够统一处理确认、鉴权展示、错误和刷新。`key` 帮 Vue 区分列表中的条目，应使用稳定的资源标识，不能只靠数组下标表示可能重排的数据。

## 6. TypeScript 的边界

```ts
interface Sandbox { id: string; status: 'Running' | 'Stopped' }
const result = await client.get<Sandbox[]>('/sandboxes')
```

`Sandbox[]` 是编译期给开发者的契约提示，**不是运行时 JSON 校验**。后端可能返回空值、未知状态、分页对象而非数组；关键入口应根据实际 API 契约处理异常响应。类型、展示标签和服务端状态枚举需要同步演进。

## 7. 不需要逐个动手练的基础模板语法

| 写法 | 作用 | 示例 |
| --- | --- | --- |
| `{{ x }}` | 文本插值 | `<p>{{ sandbox.id }}</p>` |
| `:prop="x"` | 绑定表达式 | `<button :disabled="loading">` |
| `@event="fn"` | 监听事件 | `<button @click="save">` |
| `v-if="ok"` | 条件创建或销毁 | `<Error v-if="error" />` |
| `v-show="ok"` | 保留节点，仅切换显示 | `<Panel v-show="open" />` |
| `v-for="x in xs"` | 列表渲染 | `<Row v-for="x in items" :key="x.id" />` |
| `v-model="x"` | 表单/组件值同步约定 | `<input v-model="keyword" />` |

`v-if` 与 `v-show` 的差别可能影响子组件生命周期和是否触发重新取数。看页面行为时，条件渲染的位置很重要。
