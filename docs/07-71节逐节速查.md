# 07｜71 节逐节速查：概念、最小代码、阅读重点

## 001～010：建立工程与 `setup`

### 001｜Vue 3 开篇

**概念**：先分清 Vue 在浏览器运行、业务 API 在服务端运行。**示例**：`<div id="app"></div>` 是应用挂载位置。**读代码**：打开 `index.html` 与 `src/main.ts`，找到入口，而不是把 `.vue` 当服务端模板。

### 002｜Vue 3 简介

**概念**：组件、响应式与组合式 API 构成主干。**示例**：`const open = ref(false)` 配合 `<Dialog v-if="open" />`。**读代码**：数据变化触发界面变化，浏览器内状态不等于后端事实。

### 003｜创建 Vue 3 工程

**概念**：`package.json` 描述依赖与脚本，Vite 提供开发与构建。**示例**：`npm run dev` 启动开发服务，`npm run build` 生成部署资源。**读代码**：看 `scripts` 和 `vite.config.ts`，不要假定开发代理在生产仍存在。

### 004｜编写 App 组件

**概念**：`App.vue` 是组件树的根。**示例**：`<template><RouterView /></template>`。**读代码**：如果看不到页面，检查根节点是否放了页面出口。

### 005｜一个简单的效果

**概念**：事件改变状态，模板自动更新。**示例**：`const n = ref(0); const add = () => n.value++`，模板 `<button @click="add">{{ n }}</button>`。**读代码**：沿着 `@click` 找函数，再找 `.value` 更新。

### 006｜Options API 与 Composition API

**概念**：旧风格按 `data/methods` 分组；组合式写法可按一个功能聚集代码。**示例**：`const loading = ref(false); async function load() { /* ... */ }`。**读代码**：一个仓库可能混用两种风格，理解功能边界比争论风格更重要。

### 007｜`setup` 概述

**概念**：组件建立时准备状态与逻辑。**示例**：`setup() { const n = ref(0); return { n } }`。**读代码**：组件实例多次建立，会分别运行对应逻辑。

### 008｜`setup` 返回值

**概念**：普通 `setup()` 返回供模板使用的数据或渲染函数。**示例**：`return { count, increase }`。**读代码**：看模板可访问哪些值；后面的 `<script setup>` 简化了手动返回。

### 009｜`setup` 与 Options API

**概念**：迁移代码可能同时有两种 API。**示例**：`setup() { return { id: ref('sb-1') } }` 可与旧选项并存。**读代码**：遇到 `this` 时确认它所处的 API 和可见性；新业务代码一般按项目既有约定统一风格。

### 010｜`setup` 语法糖

**概念**：`<script setup>` 顶层绑定可直接用于模板。**示例**：`<script setup>const name = 'Portal'</script><template>{{ name }}</template>`。**读代码**：无需寻找显式 `return { name }`。

## 011～025：响应式、派生状态和组件输入

### 011｜`ref` 创建基本类型响应式数据

**概念**：用包装值追踪变化。**示例**：`const count = ref(0); count.value++`。**读代码**：JS 中通常要 `.value`，模板中通常自动解包。

### 012｜`reactive` 创建对象类型响应式数据

**概念**：创建代理对象。**示例**：`const filter = reactive({ status: '', page: 1 }); filter.page++`。**读代码**：不要直接解构出普通字段后期待它继续跟随原对象变化。

### 013｜`ref` 创建对象类型响应式数据

**概念**：`ref` 也能包装对象、数组。**示例**：`const items = ref<Sandbox[]>([]); items.value = result`。**读代码**：列表请求完成后通常整体替换 `.value`。

### 014｜`ref` 对比 `reactive`

**概念**：前者容器可整体重新赋值，后者通过代理对象访问属性。**示例**：`ref({a:1}).value.a` 对比 `reactive({a:1}).a`。**读代码**：问“状态是谁持有、怎样传递”，别把二者简化成原始值/对象的硬规则。

### 015｜`toRefs` 与 `toRef`

**概念**：把响应式对象字段作为保持连接的 ref 取出。**示例**：`const { status } = toRefs(filter); status.value = 'Running'`。**读代码**：普通解构可能造成更新不再联动。

### 016｜`computed` 计算属性

**概念**：根据现有状态推导结果。**示例**：`const count = computed(() => items.value.length)`。**读代码**：推导值不应再维护一份易失同步的手动副本。

### 017｜`watch` 监视情况一

**概念**：监听 `ref`。**示例**：`watch(keyword, value => console.log(value))`。**读代码**：识别监听源和副作用；输入变化可能触发重新请求。

### 018｜`watch` 监视情况二

**概念**：监听响应式对象；深层变动行为和旧/新值要谨慎看。**示例**：`watch(filter, () => reload())`。**读代码**：对象内属性更新可能频繁触发，别假设新旧值总是两份独立快照。

### 019｜`watch` 监视情况三

**概念**：监听对象内特定属性时使用 getter。**示例**：`watch(() => filter.status, status => reload(status))`。**读代码**：`watch(filter.status, ...)` 若传入普通字符串，不是预期的响应式源。

### 020｜`watch` 监视情况四

**概念**：嵌套属性、对象替换与深度观察要按实际数据结构配置。**示例**：`watch(() => filter.options, reload, { deep: true })`。**读代码**：深度监听有成本，优先明确需要监听的字段。

### 021｜`watch` 监视情况五

**概念**：同时监听多个源。**示例**：`watch([() => filter.status, () => filter.page], reload)`。**读代码**：确认分页与过滤变化时，是否需要重置页码、避免重复请求。

### 022｜`watchEffect`

**概念**：自动收集执行过程中读取的响应式依赖。**示例**：`watchEffect(() => console.log(filter.status))`。**读代码**：复杂异步流程更要看清实际追踪了哪些依赖；不要因为代码短就忽略触发频率。

### 023｜标签的 `ref` 属性

**概念**：拿 DOM 或组件实例。**示例**：`const input = ref<HTMLInputElement|null>(null); onMounted(() => input.value?.focus())`，模板 `<input ref="input" />`。**读代码**：挂载前可能是 `null`，不宜用实例访问代替常规父子通信。

### 024｜TS 的接口、泛型、自定义类型

**概念**：描述数据契约。**示例**：`interface Sandbox { id: string }; const items = ref<Sandbox[]>([])`。**读代码**：泛型提供静态提示，不自动验证 HTTP 运行时响应。

### 025｜`props` 的使用

**概念**：父组件向子组件输入数据。**示例**：子组件 `defineProps<{ appID: string }>()`，父组件 `<Detail :appID="selected" />`。**读代码**：数据归父层所有，子层通过事件提出修改请求。

## 026～042：生命周期与路由

### 026｜理解生命周期

**概念**：创建、挂载、更新、卸载是组件经历的阶段。**示例**：`onMounted(load); onUnmounted(cleanup)`。**读代码**：首次请求在哪里触发、轮询或监听在哪里清理。

### 027｜Vue 2 生命周期

**概念**：读旧项目时识别 `mounted`、`beforeDestroy` 等名字。**示例**：`mounted() { this.load() }`。**读代码**：迁移到 Vue 3 时对照新的组合式生命周期钩子，不必为了新项目背全套旧 API。

### 028｜Vue 3 生命周期

**概念**：组合式 API 用 `onMounted`、`onUpdated`、`onUnmounted`。**示例**：`onMounted(() => window.addEventListener('resize', fn)); onUnmounted(() => window.removeEventListener('resize', fn))`。**读代码**：看资源是否成对清理。

### 029｜自定义 Hooks

**概念**：`useXxx()` 函数复用有状态逻辑。**示例**：`const { items, reload } = useSandboxList(appID)`。**读代码**：状态声明在函数内还是模块顶层，决定实例间是否共享。

### 030｜理解路由

**概念**：页面 URL 对应组件，不等于后端 API 路由。**示例**：`/apps/:appID → AppDetailView`。**读代码**：先在路由表定位页面，再沿 API 模块找服务端请求。

### 031｜路由基本切换

**概念**：`RouterLink` 跳转，`RouterView` 放页面。**示例**：`<RouterLink to="/apps">应用</RouterLink><RouterView />`。**读代码**：确认根布局中有展示子路由的出口。

### 032｜路由两个注意点

**概念**：路由组件可复用；嵌套视图要有出口。**示例**：`watch(() => route.params.appID, reload)`。**读代码**：URL 改了却显示旧数据时查参数侦听；子页空白时查父层 `RouterView`。

### 033｜路由器工作模式

**概念**：history 是正常路径，需要服务器回退；hash 在 `#` 后表示客户端片段。**示例**：`createWebHistory()` / `createWebHashHistory()`。**读代码**：刷新 404 首先查静态服务和 Ingress。

### 034｜`to` 的两种写法

**概念**：字符串或路由对象。**示例**：`<RouterLink to="/apps" />` 与 `<RouterLink :to="{ name: 'apps' }" />`。**读代码**：冒号使 `to` 变成 JavaScript 表达式。

### 035｜命名路由

**概念**：用稳定名称跳转。**示例**：`router.push({ name: 'app-detail', params: { appID: 'team-a' } })`。**读代码**：回路由表看 `name` 对应的路径和参数。

### 036｜嵌套路由

**概念**：父布局与子内容分别匹配。**示例**：`children: [{ path: 'sandboxes', component: SandboxList }]`。**读代码**：父组件需要 `<RouterView />`；可共享应用标题与导航。

### 037｜`query` 参数

**概念**：URL `?status=Running&page=2` 适合筛选/分页。**示例**：`String(route.query.status ?? '')`。**读代码**：query 可重复或缺失，类型要按项目处理；不要假设总是单个字符串。

### 038｜`params` 参数

**概念**：路径里的动态段。**示例**：`String(route.params.appID)`。**读代码**：URL 的 appID 是用户输入，后端必须验证归属。

### 039｜路由 `props` 配置

**概念**：把路由参数作为组件输入，降低组件对路由对象的耦合。**示例**：`{ path: '/apps/:appID', component: Detail, props: true }`，组件 `defineProps<{appID:string}>()`。**读代码**：参数从 Router 进入组件，而非直接读 `useRoute()`。

### 040｜`replace` 属性

**概念**：替换当前历史记录，不增加一个新记录。**示例**：`router.replace({ name: 'apps' })`。**读代码**：用于登录回跳或重定向时，浏览器返回键行为不同。

### 041｜编程式路由导航

**概念**：代码主动导航。**示例**：`await router.push({ name: 'app-detail', params: { appID } })`。**读代码**：一般出现在保存成功、点击表格行等处理函数中。

### 042｜路由重定向

**概念**：把旧路径或默认路径指向目标位置。**示例**：`{ path: '/', redirect: '/apps' }`。**读代码**：要区分前端 Router 的重定向与服务端 HTTP 3xx。

## 043～051：Pinia

### 043｜理解 Pinia

**概念**：跨组件共享的前端状态与操作。**示例**：`const auth = useAuthStore(); console.log(auth.user)`。**读代码**：它是浏览器中的应用状态，不是 MySQL、Redis 或授权服务器。

### 044｜准备一个效果

**概念**：先观察多个组件共享状态的需求。**示例**：顶部展示用户名，审批页展示同一角色，二者可读 `authStore.user`。**读代码**：只有多处共享且生命周期合理的数据才值得提升到 Store。

### 045｜搭建 Pinia 环境

**概念**：在应用入口注册 Pinia。**示例**：`app.use(createPinia())`。**读代码**：从 `main.ts` 找注册，避免在未注册的应用上下文里访问 Store。

### 046｜存储与读取数据

**概念**：Store 定义可共享状态。**示例**：`defineStore('auth', { state: () => ({ user: null as User|null }) })`。**读代码**：`useAuthStore()` 返回当前应用里的对应 Store。

### 047｜修改数据（三种方式）

**概念**：可直接赋值、`$patch` 或用 action。**示例**：`store.count++`、`store.$patch({ count: 2 })`、`store.increment()`。**读代码**：跨步骤业务操作通常封装成 action 更好追踪。

### 048｜`storeToRefs`

**概念**：解构 Store 的状态或 getter 时保留响应式。**示例**：`const { user, isAdmin } = storeToRefs(auth)`。**读代码**：方法可直接从 Store 调用，别把普通对象解构当作响应式解构。

### 049｜`getters`

**概念**：根据 Store 状态派生值。**示例**：`getters: { isAdmin: state => state.user?.role === 'Admin' }`。**读代码**：这个值仅用于界面展示判断，服务端仍要鉴权。

### 050｜`$subscribe`

**概念**：观察 Store 状态变化。**示例**：`store.$subscribe((_mutation, state) => console.log(state))`。**读代码**：检查监听的生命周期与副作用；勿把敏感会话信息随意持久化到本地存储。

### 051｜Store 组合式写法

**概念**：像 composable 一样声明状态、计算和 action，再返回。**示例**：`defineStore('counter', () => { const n=ref(0); const inc=()=>n.value++; return {n,inc} })`。**读代码**：返回的状态和方法构成 Store 对外接口。

## 052～063：组件通信与插槽

### 052｜通信方式 1：`props`

**概念**：父 → 子。**示例**：`<SandboxTable :items="items" />`；子组件 `defineProps<{ items: Sandbox[] }>()`。**读代码**：找到状态真正归属的父组件。

### 053｜通信方式 2：自定义事件

**概念**：子 → 父，报告发生的动作。**示例**：`emit('stop', id)`；父组件 `@stop="handleStop"`。**读代码**：沿事件名追到处理函数和 API 请求。

### 054｜通信方式 3：`mitt`

**概念**：事件总线，跨不相连组件发通知。**示例**：`bus.on('refresh', reload); bus.emit('refresh')`。**读代码**：谁监听、谁发送、何时 `off`；关键业务链路避免只有隐式事件。

### 055｜通信方式 4：`v-model`

**概念**：父子之间的值更新约定。**示例**：父 `<Dialog v-model="open" />`；子接收模型值并发更新事件。**读代码**：双向写法仍需有明确的状态所有者。

### 056｜`v-model` 细节

**概念**：组件可给模型命名，或在支持的版本用 `defineModel`。**示例**：`<Filter v-model:status="status" />`；对应 `status` 与 `update:status`。**读代码**：确认模型参数名字，不要把原生输入的 `v-model` 与组件模型实现混为一谈。

### 057｜通信方式 5：`$attrs`

**概念**：未声明为 props 或 emits 的属性/监听可透传。**示例**：包装组件 `<input v-bind="$attrs" />`。**读代码**：`class`、`disabled`、事件最终落在谁身上；有多个根元素时更应显式检查。

### 058｜通信方式 6：`$refs` 与 `$parent`

**概念**：从实例层面直接访问。**示例**：父组件 `const dialog=ref<InstanceType<typeof Dialog>|null>(null)`，子组件 `defineExpose({ open })`。**读代码**：用来调用聚焦、打开等有限命令较常见；大量读取子内部状态会提高耦合。

### 059｜通信中的一个注意点

**概念**：组件实例关系、公开成员与实际模板引用必须对应。**示例**：`dialog.value?.open()` 需要子组件确实暴露 `open`。**读代码**：遇到访问不到成员时检查 `defineExpose`、挂载时机及 `v-if` 是否销毁了组件。

### 060｜通信方式 7：`provide/inject`

**概念**：祖先给后代提供数据，无需层层传 props。**示例**：`provide('appID', appID)`；后代 `const appID = inject<Ref<string>>('appID')`。**读代码**：从当前组件向上找最近提供者；真实项目可用 `InjectionKey` 避免字符串键冲突。

### 061｜默认插槽

**概念**：父组件把界面内容填到子组件预留的默认位置。**示例**：子 `<section><slot /></section>`；父 `<Card>详情内容</Card>`。**读代码**：内容由使用者提供，布局由 Card 提供。

### 062｜具名插槽

**概念**：一个组件预留多个位置。**示例**：子 `<slot name="title" />`；父 `<template #title>网络策略</template>`。**读代码**：标题、底部操作、单元格等内容从哪里来。

### 063｜作用域插槽

**概念**：子组件提供局部数据给父层编写的模板。**示例**：子 `<slot name="cell" :row="row" />`；父 `<template #cell="{ row }">{{ row.id }}</template>`。**读代码**：`row` 是槽出口提供的值，并非自动成为全局变量。

## 064～071：高级响应式与其他能力

### 064｜`shallowRef` 与 `shallowReactive`

**概念**：只追踪浅层，适合明确控制大型对象更新等场景。**示例**：`const state = shallowRef({ n: 1 }); state.value = { n: 2 }`。**读代码**：深层原地修改不一定触发预期刷新；需理解替换边界。

### 065｜`readonly` 与 `shallowReadonly`

**概念**：向使用方暴露只读视图；浅只读仅限制第一层。**示例**：`const publicState = readonly(state)`。**读代码**：这是前端修改约束，不是权限或数据安全边界。

### 066｜`toRaw` 与 `markRaw`

**概念**：获取代理背后的原对象，或让对象跳过响应式转换。**示例**：`const raw = toRaw(state); const chart = markRaw(new Chart(...))`。**读代码**：多用于第三方实例或特定优化，不要日常拿原对象改值后期待 Vue 自动更新。

### 067｜`customRef`

**概念**：自己决定何时追踪和触发变更。**示例**：`customRef((track, trigger) => ({ get(){track(); return value}, set(v){value=v; trigger()} }))`。**读代码**：常见案例是防抖输入；先搞清触发时机再排查界面更新。

### 068｜`Teleport`

**概念**：把部分 DOM 渲染到指定目标位置，组件逻辑关系仍然保留。**示例**：`<Teleport to="body"><Dialog /></Teleport>`。**读代码**：弹窗可能在 `body` 下，却仍从原组件接收 props 和事件。

### 069｜`Suspense`

**概念**：对异步组件/依赖提供加载边界。**示例**：`<Suspense><AsyncPanel /><template #fallback>加载中</template></Suspense>`。**读代码**：并非所有普通 HTTP 取数都会自动进入这里的 fallback；先看实际异步依赖如何声明。

### 070｜全局 API 转移到应用对象

**概念**：Vue 3 更强调按应用实例配置。**示例**：`const app = createApp(App); app.component('StatusTag', StatusTag); app.mount('#app')`。**读代码**：看 `main.ts` 的插件、组件及全局配置装配。

### 071｜Vue 3 的非兼容性改变

**概念**：迁移 Vue 2 项目需逐项核对差异。**示例**：旧 `new Vue({ ... })` 对照新 `createApp(App).mount('#app')`。**读代码**：新项目先按 Vue 3 文档理解；维护旧项目时参考[官方迁移说明](https://v3-migration.vuejs.org/)，不要机械替换名字。
